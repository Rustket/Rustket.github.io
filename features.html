Installed with care.

Rustket brings a straightforward package workflow to macOS and Linux: packages come from GitHub taps, downloads are checked, and installed commands are ready in one place.

Get started
01

Integrity checks

Know what was downloaded.

A bit definition includes a download URL and the archive's SHA-256 digest. During installation Rustket calculates the archive's digest and compares it with that value before unpacking. A mismatch stops the install instead of silently continuing.

Verification is on by default. --skip-verify is available for development, but skips this check.
release.tar.gzSHA-256
a84f 2b19 7c03 5e61
d1aa 98c2 4e0f b772
✓ Digest matches
02

GitHub taps

Packages stay transparent.

A tap is a GitHub repository with package definitions in a bits/ directory. Each TOML definition names the package, version, platform-specific archive URL, checksum, and executable path. Add a tap using owner/repo or its GitHub HTTPS URL, then refresh it with Git.

rustket tap add owner/repo
bits/hello.tomlTOML
name = "hello"
version = "1.0.0"

[platform."linux-x86_64"]
url = "https://github.com/..."
sha256 = "..."
bin = "hello"
03

Organized installs

Packages have a place.

Rustket unpacks each package under ~/.rustket/cellar/<name>/<version> and links its executable into ~/.rustket/bin. This separates installed files from the commands you invoke and makes the managed binaries easy to find.

rustket list   ·   rustket uninstall <bit>
⌂ ~/.rustket/
├── cellar/
│   └── ripgrep/14.1.1/
└── bin/
└── ripgrep → cellar/...
04

Cross-platform releases

One workflow across systems.

Rustket's 0.1.0 prebuilt releases cover macOS and Linux on ARM64 and x86_64. Bits can describe a separate archive for each platform. If a bit does not include a build for the current platform, Rustket reports that it is unavailable.
